# 学习总结

跑完 11 个模型之后，真正学到的东西不是「哪个模型最好」，而是下面这几条。

## 1. 表示方法的提升不是单调的

按时间顺序，文本表示的演化是 Bag of Words (1950s) → Word2Vec (2013) →
GloVe (2014) → BERT (2018)。很容易以为准确率会跟着单调上升。实测不是：

| 表示 | 验证准确率 |
|---|--:|
| Bag of Words + 随机森林 | 0.8254 |
| 自训 Word2Vec 向量平均 + 随机森林 | **0.7994** ← 比词频统计更差 |
| TF-IDF (1-2gram) + 逻辑回归 | **0.8952** ← 稀疏特征打过了所有 GloVe 模型 |
| GloVe（预训练静态词向量）+ 各种神经网络 | 0.8760 ~ 0.8936 |
| BERT 系（上下文词向量，全模型微调） | 0.9090 ~ **0.9292** |

**「更先进的表示 + 更差的聚合方式」可以整体倒退。** Word2Vec 向量平均输给词频统计，
不是词向量不行，是「平均」这一步把词序、否定和强度全抹掉了：
`not good` 和 `good not` 平均出来一样。

这件事的推论是：**表示方法和聚合方式必须一起看。**
GloVe 之所以能到 0.89，一半功劳在 CommonCrawl 8,400 亿词的预训练规模，
另一半在 CNN / LSTM / Attention 学会了怎么聚合，而不是取平均。

## 2. 在单领域二分类上，稀疏特征 + 线性模型是极强的基线

TF-IDF (1-2gram) + 逻辑回归拿到 0.8952，用 16 秒 CPU 训练，
打过了所有 GloVe 神经网络（0.8876 ~ 0.8936），后者需要 GPU 和 1~5 分钟。

三处改动就把稀疏特征从 0.8254 拉到 0.8952：

1. **TF-IDF 替代原始计数**——降低高频泛用词的权重；
2. **加入 bigram**——`not good` 成为独立特征。纯 unigram 看到的是 `not` 和 `good`
   两个正交维度，否定关系完全丢失；
3. **线性模型替代随机森林**——20 万维稀疏空间里，决策树每次分裂只看一个维度，
   效率很低；逻辑回归对所有维度加权求和，天然契合这种特征。

所以「上深度学习」之前，先把这个基线打好——很多时候它就够了。

**真正拉开差距的是预训练规模，不是模型结构。**
把静态的 GloVe 换成上下文相关的 BERT 系，准确率一下从 0.89 跳到 0.93：

| 模型 | 验证准确率 | 训练时间 | 参数量 |
|---|--:|--:|--:|
| TF-IDF + 逻辑回归 | 0.8952 | 16 s | 20 万（特征维度） |
| GRU + GloVe（最好的 GloVe 模型） | 0.8936 | 283 s | 56.5 万可训练 |
| DistilBERT | 0.9090 | 242 s | 6,696 万 |
| BERT-base | 0.9194 | 544 s | 1.09 亿 |
| **RoBERTa-base** | **0.9292** | 555 s | 1.25 亿 |

注意 **BERT 和 RoBERTa 的结构几乎一样**，差的只是预训练配方
（RoBERTa 去掉了 NSP、改用动态遮盖、语料从 16 GB 加到 160 GB），
就换来 1 个百分点。而结构上花样最多的 Capsule-LSTM（动态路由）
和从零训的 Transformer，都没能超过最朴素的 GRU。

这条经验很直接：**同样的算力，投在「用更好的预训练权重」上，
回报远高于投在「设计更复杂的结构」上。**

**DistilBERT 是性价比拐点**：只用 BERT 一半的时间（242 s vs 544 s）、
60% 的参数，拿到 0.9090——比所有 GloVe 模型都高。
资源受限时它是默认选择。

## 3. GRU / LSTM / CNN 之间的差距，比想象的小得多

| 模型 | 验证准确率 | 训练时间 | 可训练参数 |
|---|--:|--:|--:|
| CNN | 0.8876 | 98 s | 461,954 |
| CNN-LSTM | 0.8910 | 64 s | 314,498 |
| Attention-LSTM | 0.8922 | 305 s | 902,402 |
| LSTM | 0.8894 | 293 s | 753,602 |
| GRU | 0.8936 | 283 s | 565,442 |

准确率全部落在 0.888 ~ 0.894 这个 0.6 个百分点的区间里，
而训练时间差了 5 倍、参数量差了 3 倍。

**GRU 对 LSTM**：GRU 少一个门，参数少 25%（565K vs 754K），
每 epoch 快约 1 秒，准确率还高 0.4 个点。在这个任务上 GRU 是更好的默认选择。
LSTM 的额外记忆单元 `c` 在几百词的情感分类上没有体现出优势——
这类任务的判别信号是局部的情感词，不是需要跨越几百步的长依赖。

**CNN-LSTM 是个意外的性价比冠军**：CNN 层把序列从 512 压到 256，
LSTM 的时间步少一半，训练时间从 293 秒降到 64 秒（快 4.6 倍），
参数还最少（314K），准确率却比纯 LSTM 高。

## 4. 「不报错但训不出来」是最贵的一类 bug

原始代码里五个实质性错误，全都不抛异常、loss 也在下降：

- 序列填到 512，`states[-1]` 读的全是 PAD——句尾信息被冲掉；
- CNN-LSTM 把卷积核维度当成时间步——LSTM 在无序集合上做顺序建模；
- Attention 的 `softmax(dim=1)` 归一化到 batch 维——batch_size 一改结果就变；
- Capsule 的 `squash` 写成纯 L2 归一化——所有胶囊长度都是 1，置信度信息被抹平；
- Transformer 的分词函数返回字符串，词表逐字符构建，退化成 26 个字母。

这类 bug 的共同点是**形状对得上、语义错了**。防御手段只有一个：
写针对语义不变量的测试，而不是只看形状。`tests/test_models.py` 里的四条就是这么来的：

```python
test_padding_does_not_change_prediction   # 补 PAD 不该改变预测 → 钉住第 1 条
test_attention_weights_sum_to_one         # 每行和为 1、PAD 位置为 0 → 钉住第 3 条
test_capsule_squash_keeps_length_below_one # 长度必须在 (0,1) → 钉住第 4 条
test_encode_texts_matches_training_pipeline # 推理编码 == 训练编码
```

这 37 项测试不需要 GPU、不需要 pickle、不需要 GloVe，2.8 秒跑完。

## 5. 评测口径比模型选择更容易出错

- **OOV 率**按词型算 22.23%，按词次算 0.43%。同一份数据，两个口径差 50 倍。
  报数字必须说清口径。
- **划分必须固定且分层**。原始的三个 BERT 脚本 `train_test_split` 连
  `random_state` 都没有——每次划分都不同，三个模型的准确率互相不可比，
  和 CNN / LSTM 更不可比。整个项目统一 `test_size=0.2, random_state=42, stratify=y`
  之后，对比表里的数字才有意义。
- **词表只能在训练分片上 fit**。否则验证集的词频分布会泄漏进特征空间，指标偏高。
- **不能用最后一个 epoch 的权重**。实测 CNN 在 epoch 5 达到 0.8876，
  epoch 10 掉到 0.8850，`val_loss` 从 0.29 涨到 0.35——已经明显过拟合。
  按 `val_acc` 存最佳权重是必须的，不是可选优化。

## 6. Attention 的可解释性是真的能看

修好 Attention 之后，权重明确压在情感词上：

```
[positive] wonderful(0.167), absolutely(0.150), superb(0.130), acting(0.092)
[negative] waste(0.124), terrible(0.117), time(0.102), script(0.091), wooden(0.058)
```

512 个位置，权重集中在前几个情感词上（单个词能拿到 12~17%，
均匀分布的话每个位置只有 0.2%）。这解释了早期 Attention 到底解决了什么：

纯 LSTM 必须把整条评论压进一个固定长度的向量，几百个词挤在 240 维里——
**信息瓶颈**。最大池化缓解了这点，但它是硬性 argmax，只留一个位置。
Attention 让模型自己学一个打分函数，软性地加权求和，
**副产品就是可解释性**。

而 Transformer 的 self-attention 又往前一步：查询向量不再是全局共享的一个参数，
而是每个位置自己生成 Q/K/V，得到的是 n×n 的关系矩阵而不是 n 维权重向量。
从「哪些词对任务重要」到「对第 i 个词来说哪些词重要」——这是通向大模型的那一步。

## 7. 工程细节决定能不能跑完

- **磁盘**：GloVe 840B 准备阶段峰值占 10 GB（zip 2.1 + txt 5.3 + kv 2.5）。
- **加载**：Gensim 原生 `.kv` 配 `mmap='r'` 从分钟级降到秒级，
  比每次重新读 5.3 GB 文本快两个数量级。
- **显存**：`train_loss += loss` 累加带计算图的张量，一个 epoch 下来显存单调增长。
- **日志**：tqdm 进度条重定向到文件时，一次 CNN 训练产生了 458 KB 的进度条残片。
  `disable=not sys.stderr.isatty()` 一行解决。
- **学习率**：照抄原代码的 `Adam(lr=0.05)` 在 LSTM 上第一个 epoch 就发散到 0.5
  （等于瞎猜）。RoBERTa 微调用 5e-5 会塌成全预测同一类，必须降到 1e-5。

这些都不是「算法问题」，但每一条都能让一次实验白跑几十分钟。

## 一句话

**这个项目里，准确率的提升主要来自「更好的预训练表示」，而不是更复杂的模型结构：
0.83（词频）→ 0.89（GloVe / TF-IDF）→ 0.93（BERT 系）这三级台阶，
每一级都是表示方法换代带来的，而同一级里换结构（LSTM / GRU / Capsule / Transformer）
只在 0.6 个百分点内浮动。而能不能得出可信的结论，取决于评测口径是否统一——
这一点比选哪个模型都重要。**
